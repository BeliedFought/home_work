# AGENTS.md

Соответствует стандарту: 4.14.3

Этот файл содержит инструкции для AI-агентов при работе с данным проектом.

## Обзор проекта

Сведения о проекте - в разделе «Специфика репозитория».

- Точки входа сессии (читать первыми):
  - @doc/standards/_index_standards.md - индекс пакета стандартов (реестр, карта маршрутизации, версия пакета)
  - индекс навыков репозитория: в хабе - @doc/skills/_index_skills_hub.md, в производных репо - doc/skills/_index_skills_repo.md
  - @doc/specs/_index_specs.md - индекс спецификаций
- Тег `@doc/standards/_index_standards.md` без конкретной задачи - команда автоактуализации индекса, а не команда ознакомления (процедура - в самом индексе, раздел «Автоактуализация индекса»)

## Выполнение задач

- Точечные изолированные задачи (поиск в репозитории, анализ и чтение файлов, аудит, проверки, подготовка отчетов) выполнять через субагентов, а не в контексте основной сессии
- Основной агент: уточнение требований, декомпозиция, постановка задач субагентам, сводка результатов, коммуникация с пользователем
- Делегирование избыточно: одиночное чтение файла, прямой ответ на вопрос, задачи, требующие диалога с пользователем

## Принятие решений

Канон - `project_standards.md`, раздел 07.06. Не выдумывать - проверять:

- Триггеры обязательной проверки: незнакомый API, сигнатура, параметры библиотеки; любое сомнение в поведении, версии или совместимости библиотеки, фреймворка, SDK; новая зависимость или версия; выбор паттерна или подхода; ошибка, не объяснимая локальным кодом
- Каскад проверки: локальный контекст (код, зависимости, стандарты) -> документация библиотеки (context7) -> GitHub (README, примеры, issues) -> поиск по тексту ошибки
- Контекст-сервер документации (context7): при любом сомнении в API, сигнатуре, версии или поведении библиотеки - обращаться к нему сразу; запрос не требует отдельного обоснования
- Ключевое решение (библиотека, паттерн, подход, версия) - с ссылкой на источник; проверить нельзя (в том числе сеть недоступна) - вопрос пользователю вместо гипотезы
- Дополнение или изменение каскада на уровне репозитория - только проектным оверрайдом (`doc/specs/overrides.md`)
- Иерархия источников: диалог -> индексы -> оверрайды -> прецедент репозитория -> интернет -> практики -> собственное решение

## Git и коммиты

- Одна ветка `master`; Conventional Commits: `<type>(<scope>): ...` или `<type>: ...` (scope опционален), инфинитив, с маленькой буквы, без точки в конце
- Типы: `feat`, `fix`, `refactor`, `chore`, `docs`, `test`, `style`
- В сообщениях коммитов и комментариях к коду не указывать, что изменения выполнены AI-агентом
- Авторство коммита - от хоста, не хардкодить: значения вычислять из `whoami`/`hostname` и хранить в локальном конфиге репозитория, перед каждым коммитом сверять и обновлять при несовпадении (канон - раздел 06.01)

## Политика AGENTS.md и CLAUDE.md

- Инструкции для агентов ведет только `AGENTS.md`; `CLAUDE.md` опционален и по умолчанию не ведется
- По умолчанию `CLAUDE.md` удаляется при синхронизации; ценное содержание перенести в `AGENTS.md` до удаления
- Если `CLAUDE.md` присутствует в репозитории - убедиться, что действует репо оверрайд (явный запрос пользователя): файл ведется зеркалом `AGENTS.md`, эталон зеркала - `CLAUDE.md` хаба
- Исключение - хаб `project_standards`: `CLAUDE.md` ведется здесь постоянно как эталон зеркала (без записи в `doc/specs/overrides.md`); в производных репозиториях действует общий порядок
- Язык `AGENTS.md` - русский; английский - по явному запросу пользователя

## Навыки: общие соглашения

- Типы навыков (слаг `type`): хаб-навык `hub_loc` (префикс `hub-`; в производные репо не распространяется), общий `hub_glob` (префикс `glob-`; распространяется во все репо), проектный `pr_glob` (префикс `pg-` / `pg_`), локальный `pr_loc` (префикс `pl-` / `pl_` опционален; только в `data/skills/`, вне синхронизации)
- Именование по формату: плоские файлы - префикс с подчеркиванием (`hub_`, `glob_`, `pg_`, `pl_`), каталоги формата Anthropic - с дефисом (`hub-`, `glob-`, `pg-`, `pl-`)
- Форматы: плоские `*.md` (plain-формат, `doc/standards/skill_plain_standards.md`) и каталоги `doc/skills/<name>/SKILL.md` (формат Anthropic, `doc/standards/skill_anthropic_standards.md`); тип фиксируется в frontmatter - `type` (plain) или `metadata.type` (Anthropic)
- Индексы навыков: `_index_skills_hub.md` (весь хаб, ведет `hub-sync-indexes`), `_index_skills_repo.md` (порепозиторный, ведет `glob-update-indexes`) и `data/skills/_index_skills_pl.md` (локальные навыки репо, ведет `glob-update-indexes`; при наличии каталога)

## Безопасность

- Не хардкодить секреты и ключи в код и конфигурацию

- Любое удаление файлов и папок в репозитории агентом - перенос в `.trash/<slug>_<YYYYMMDDHHMM>/` (карантин, `project_standards.md` 01.01.06), а не удаление; чистить `.trash/` только по явному запросу пользователя

## Границы

- Серьезные правки - только после триггера пользователя `ДЕЛАЙ` или `GO`; триггер действует на одну задачу (раздел 07.02)
- Спросить сначала: крупные рефакторинги, новые зависимости, деструктивные операции (перезапись данных, миграции БД)
- Никогда: коммитить секреты, править генерируемые файлы руками при наличии генератора, деструктивный git без явного запроса
- Не бампить версию пакета стандартов без явного запроса пользователя

## Специфика репозитория: home_work

## Назначение

Репозиторий-контейнер для решения домашних учебных задач, в основном по программированию (основной язык - Python, встречаются SQL и базы данных). Работа сессионная: одна задача - одна сессия в папке `sessions/`.

Сам контейнер runnable-проектом не является: в корне нет `config/`, `src/`, `.venv`. Каркас и окружение создаются внутри сессии по потребности задачи. Отклонение от `project_standards.md` 07.03 зафиксировано в `doc/specs/overrides.md`.

Источник истины: `README.md` (структура для человека), этот файл (правила агента), `doc/specs/overrides.md` (отклонения от стандарта). Пакет `doc/standards/` - копия хаба `project_standards`, доступна только для чтения (раздел 07.05 стандарта).

## Поиск задания

Задания обычно приходят скриншотами из Telegram. Порядок:

1. Искать свежие изображения в загрузках Telegram: `~/Downloads/Telegram Desktop/` (файлы вида `photo_YYYY-MM-DD_HH-MM-SS.jpg`), при необходимости - `~/Pictures/Screenshots/`
2. Отобрать самые новые по времени изменения; задачи на нескольких скриншотах читать все, собирая единую картину
3. Извлечь условие, пример входа и выхода, язык, ограничения и комментарий учителя
4. Условие записать в спецификацию сессии; все собранные по заданию скриншоты сохранить постоянными артефактами в `doc/screenshots/` сессии (папка коммитится)

Методика поиска источников решения при неясностях - в навыке `pg-search-sources`.

## Структура репозитория

Полная таблица - в `README.md`. Поведенческие правила:

- `sessions/` - контейнер сессий; каждая задача - отдельная папка с `SESSION.md`; вложенные сессии и `SESSION.md` в корне репозитория запрещены
- Каркас сессии - по потребности задачи (для Python-задачи: `src/`, `run/`, `data/`, `doc/specs/`, `requirements.txt`); лишние папки не создаются
- `input/` и `output/` в сессии создаются, только когда задача читает или пишет файлы: `input/` - входящие данные, `output/` - результаты. Папка коммитится через `.gitkeep`, содержимое локально и в git не попадает (разделы 01.01, 06.01 стандарта); задачи на стандартный ввод/вывод их не требуют
- `doc/standards/` - только чтение; правится только в хабе `project_standards`
- `doc/specs/` - спецификации репозитория и оверрайды (`overrides.md`)
- `doc/skills/` - общие `glob-*` (только чтение, приходят синхронизацией) и проектные `pg-*`
- `doc/change_requests/` - задания на изменение (CR), коммитится с индексом
- `doc/agent_questions/` - транзитная: не коммитится, кроме `.gitkeep`
- `.trash/` - карантин; локальная, не коммитится

## Навыки репозитория

Полный реестр - в `_index_skills_repo.md`. Проектные навыки (подробности - в `SKILL.md`):

- `pg-search-sources` - порядок поиска источников решения: каскад 07.06, context7 для библиотек, GitHub для практик и аналогов, веб-поиск для ошибок

Общие навыки `glob-*` приходят из хаба синхронизацией и здесь не редактируются.

## Типичные scope коммитов

`session` (работа в сессии), `sessions` (инфраструктура контейнера), `docs`, `skills`, `config`; идентификатор сессии в scope коммита - по разделу 01.01.01 стандарта (например `feat(2026-09-24_new-number): добавить решение`).

## Особенности

- Задачи проверяются автоматически: программа читает данные со стандартного ввода и печатает ответ в стандартный вывод. Формат вывода должен совпадать с ожидаемым точно; лишние строки, отладочный вывод и пояснения недопустимы (оверрайд в `doc/specs/overrides.md`)
- Учебные сессии по задачам с автопроверкой не используют логгер, локализацию и конфигурацию; каркас сессии минимален
- Решение укладывается только в конструкции, пройденные в школе (по комментарию учителя в задании); пользовательские функции, импорты, генераторы и продвинутые приемы не применяются, если это не задано условием. Какие конструкции разрешены - записывается в спецификацию сессии
- Все скриншоты, собранные по заданию, хранятся постоянными артефактами в `doc/screenshots/` сессии и коммитятся; спецификация с условием также коммитится
- `doc/specs/ui_spec.html` - универсальный шаблон хаба; собственный UI-эталон создается в сессии, только если задача выводит данные пользователю и требует оформления
- Пакет стандартов обновляется только через хаб `project_standards` (навык `hub-sync-standards`); в этом репозитории `doc/standards/` не правится
