# Поиск источников решения учебных задач

Локальный навык репозитория `home_work` (слаг `pr_loc`, без префикса, `data/skills/`). Определяет, откуда брать информацию при решении задач, чтобы не выдумывать и давать ответ со ссылкой на источник.

Канон порядка принятия решений - `project_standards.md`, раздел 07.06; настоящий навык его не заменяет, а применяет к учебным задачам. Общее правило: решение берется с первого уровня каскада, давшего однозначный ответ.

## Когда использовать

- Незнакомый API, сигнатура, параметры библиотеки или функции
- Любое сомнение в поведении, версии или совместимости библиотеки, фреймворка, SDK
- Выбор подхода, паттерна или алгоритма
- Ошибка, не объяснимая локальным кодом
- Нужно подтвердить факт источником, а не памятью

Навык не нужен для тривиальных задач, где ответ однозначен из условия и стандартной библиотеки.

## Инструкция

### 1. Каскад источников

Порядок поиска сверху вниз, до первого надежного источника:

1. Явные указания пользователя текущего диалога
2. Локальный контекст: код сессии, зависимости (`requirements.txt`), пакет стандартов в `doc/standards/`
3. Документация библиотеки через контекст-сервер context7
4. GitHub MCP: README, примеры, issues, код реальных проектов
5. Веб-поиск и загрузка страниц: официальная документация, обсуждения, тексты ошибок
6. Общепринятые практики платформы - ниже интернета, апелляция «так принято» без источника основанием не является
7. Собственное решение - только если предыдущие уровни не дали ответа

### 2. Где что искать

- **Документация библиотек, фреймворков, SDK** - context7 (`tools["context7"]`, `resolve-library-id` затем `query-docs`). Обращаться при первом сомнении, отдельное обоснование не требуется
- **Практики, аналоги, реальный код** - GitHub MCP (`tools["github"]`): `search_code`, `search_repositories`, `search_issues`, чтение README и файлов. Приоритетный источник для «как решают другие» и «какие есть аналоги»
- **Текст ошибки** - веб-поиск (`websearch`) и загрузка страниц (`webfetch`); для Python дополнительно официальная документация `docs.python.org` и документация стандартной библиотеки
- **SQL и базы данных** - документация СУБД (context7 или официальный сайт), спецификации SQLite/PostgreSQL
- **Формулировки условий задач** - исходный скриншот задания в `input/` сессии; при неоднозначности сверить с примером входа и выхода

### 3. Проверка фактов

- Сработал маркер проверки (пункты раздела «Когда использовать») - сначала искать источник, не отвечать по памяти
- Ключевое решение (библиотека, паттерн, подход, версия) сопровождать ссылкой на источник в ответе пользователю
- Сеть недоступна или источник не найден - остановиться и задать вопрос пользователю; ответ гипотезой без пометки «не проверено» недопустим
- Не использовать в учебной задаче стороннюю библиотеку без необходимости: предпочитать стандартную библиотеку и явное согласование новых зависимостей

### 4. Границы

- Источник вторичен по отношению к условию задачи и автоматической проверке: главный критерий - корректный вывод программы, а не «красота» решения
- Не копировать готовое решение целиком; брать идею, алгоритм или факт и реализовывать по правилам `code_standards.md`
- Секреты и ключи из внешних источников в репозиторий не попадают

## Критерии завершения

- Для каждого неочевидного факта или решения указан источник
- Использована стандартная библиотека, где возможно
- При недоступности источников задан вопрос пользователю, а не придуман ответ
