Спецификация UI: эталон кадров и методика

Версия макета: 1.5.0. Репозиторий: project_standards (хаб). Этот файл - универсальный шаблон структуры doc/specs/spec_ui.html для любого репозитория.

Примеры кадров иллюстративны. При расхождении примеров с методикой побеждают: (1) doc/standards/console_ui_standards.md, (2) раздел 06 «Методика проекта» ниже, (3) код. Доменные строки - из t() / translations, не выдумывать.

01. Как сформировать макет (инструкция агенту)

Нормативный контракт кадра, клавиш, ролей, двух каналов - только в doc/standards/console_ui_standards.md. Этот HTML - эталон проекта: карта, кадры, лог, доменные контракты.

  1. Скопировать структуру этого файла в doc/specs/spec_ui.html целевого репо (или обновить существующий, сохранив разделы 02-06 и футер).
  2. Заголовок / meta: заменить имя репозитория; выставить Версия макета: X.Y.Z (своя SemVer, не версия приложения и не версия пакета стандартов). При любом изменении кадров/карты/лога/методики - bump макета в том же изменении.
  3. Раздел 02. Карта:
    • есть menu - дерево экранов и переходов (включая «Назад», «Главное меню», условные пункты, batch CLI вне меню);
    • нет menu - карта точек вывода (plain / rich / GUI / docs-only).
    Без карты эталон неполон.
  4. Раздел 03. Палитра: зафиксировать hex ролей проекта (имена ролей не менять: заголовок, навигация, ключ-цифра, ключ-служба, текст пункта, команда, prompt, статус успех/нейтраль/ошибка). Обновить CSS :root под эти hex. По запросу пользователя - можно сменить hex и шрифт кадров; после смены - bump SemVer макета.
  5. Раздел 04. Кадры: для каждого значимого экрана - карточка с цветным пре-рендером. Порядок блоков кадра (обязателен): breadcrumb → пункты → тело → пустая → [>] внизу. Использовать классы c-breadcrumb c-nav c-title c-key c-svc c-text c-prompt c-ok c-dim c-err c-cmd. Плейсхолдеры {t("...")} допустимы. Если UI нет - явно написать «кадров нет» и не удалять раздел.
  6. Раздел 05. Лог: обязательные фрагменты plain-ленты (YYYY-MM-DD HH:MM:SS [маркер] сообщение), без ANSI и без clear. Показать те же сценарии, что в кадрах (смысловые строки; таблицы в логе - по иерархии стандарта).
  7. Раздел 06. Методика проекта (заполнить слоты, не копировать smb-домен):
    • контракт «после какого действия какой экран»;
    • условные пункты меню;
    • статусы / единицы / допустимые хардкоды;
    • временные исключения цифр (если есть - явно «временно»);
    • batch CLI вне меню (если есть);
    • источник истины рантайма (пути к menu.py, console_table.py, translations).
  8. TOC: синхронизировать ссылки с реальными id секций (при добавлении экранов - пункты 04.02, 04.03 и далее).
  9. Футер: полный абсолютный путь к этому файлу + xdg-open + file:// (см. низ файла). В шаблоне хаба - плейсхолдер /home/<user>/<repo>/; при копировании в целевое репо агент заменяет его на фактический абсолютный путь этого репозитория. Относительный путь недостаточен.
  10. Согласовать с пользователем до реализации UI (см. project_standards.md 07.03). После правок кода - реверс макет ↔ код (glob-audit-repository).
  11. Batch CLI: если есть пакетный прогон вне меню - в разделе 02 карта точек вывода; в разделе 04 кадры по образцу 01.01 (баннер → секции → прогресс → одна таблица → сводки); в разделе 06.06 - колонки, статусы, шаблоны сводок, --dry-run если мутации; прогресс в лог не попадает. Rich только в интерактивном контексте (TTY и не CI/TERM=dumb).

01.01. Образец: batch CLI (порядок кадра + прогресс)

Методика кадра - console_ui_standards.md (раздел 04.04). Копировать в раздел 04 целевого репо при наличии batch; доменные строки заменить на t(). Это обобщенный порядок, не макет конкретного приложения.

Порядок batch-кадра mode=rich образец
{t("msg.app_started", name=APP_NAME, version=APP_VERSION)} {t("title.params")} {t("label.param_a")}: value_a {t("label.param_b")}: value_b {t("title.batch_section")} ▸ {t("msg.item_name")} ━━━━━━━━━━━━━━╸━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━ 17% 04/23 {t("title.table")} ╭──────────┬──────────────╮ │ Имя │ Статус │ ├──────────┼──────────────┤ │ alpha │ ok │ │ beta │ skip │ │ gamma │ error │ ╰──────────┴──────────────╯ {t("msg.summary_total")}: ok: 1, skip: 1, err: 1

Сверху вниз: баннер старта (без секции) → стартовые секции → при длительном прогоне двухстрочный прогресс (заголовок → активный элемент с маркером ▸/> → бар ширины 40 + % + zero-pad счетчик; step до работы, advance после) → одна таблица статусов → цветные сводки (раздел 03.04 console_ui_standards.md). Вне интерактивного контекста прогресс и цвет не рисуются; те же смысловые строки - в plain-лог. Прогресс в лог не пишется.

02. Карта навигации / точек вывода

Заполнить дерево. Ниже - пример заполнения для хаба (docs-only). В приложении с меню - заменить на дерево экранов с ключами [Z]/[1..N] и переходами.

Репозиторий project_standards (docs-only)
├── нет mode=menu / mode=rich / GUI
├── нет src/menu.py, console_table.py, rich_console.py, console_summary.py
└── вывод - документация и чат (не TTY-кадр приложения)

Шаблон дерева для проекта с меню (заменить при заполнении):
{t("app.name")} / Главное меню
├── [Z] {t("menu.section_a")}          → экран A
│   ├── [1..N] действие по строке      → по контракту раздела 06.02 (main / stay+pending)
│   ├── [Z] пакетное действие
│   ├── [X] {t("menu.back")}
│   └── [C] {t("menu.main_menu")}
├── [X] {t("menu.section_b")}
└── [V] {t("menu.exit")}
Вне меню (CLI): <команда batch>     (если есть)

03. Палитра ролей (hex проекта)

Имена ролей стабильны (console_ui_standards.md). Hex и шрифт кадров - только здесь и в CSS :root / font-family; по явному запросу пользователя их можно менять (имена ролей и контракт кадра - нет). Ниже - значения шаблона.

заголовок      #4ec9b0   breadcrumb (bold)
навигация      #4ec9b0   «Назад» / «Главное меню» (тон breadcrumb, без bold)
секция/title   #4ec9b0   title таблицы, заголовки секций (без bold)
ключ-цифра     #dcdcaa   [1], колонка # (bold)
ключ-служба    #ce9178   [Z] [X] [C] [V]
текст пункта   #d4d4d4   подпись пункта / префикс сводки
команда        #6a9955   встроенный CLI в тексте (bold)
prompt         #dcdcaa   [>] (bold, тон ключ-цифры)
статус успех   #4ec9b0   ok / активное
статус нейтраль #808080  dim / пропуск / 0
статус ошибка  #f44747   отказ / сбой
